# 군체 저항도

사용자가 제공한 10개의 생존 상황으로 진행하는 한국어 행사 웹앱입니다. QR 접속, 이름·학번 등록, 문항별 실시간 비율, 마감 시 확정 점수, 운영자 추첨을 제공합니다.

## 행사 운영 순서

1. 현재 배포는 사용자 승인에 따라 `PUBLIC_ADMIN_ACCESS=true`인 **공개 운영실**입니다. 누구나 로그인·비밀번호 없이 명단·CSV와 행사 시작·마감·추첨 기능을 이용할 수 있습니다. 비공개로 되돌리려면 이 값을 `false`로 바꾸고 다시 배포합니다. 비공개 모드에서는 `ADMIN_EMAILS`에 등록한 실제 운영자의 ChatGPT 계정만 허용하며, 목록이 비어 있으면 접근을 거절합니다.
2. `SITE_URL`에 배포 도구가 반환한 정확한 HTTPS 사이트 주소를 설정하고 다시 배포합니다. 이 값은 변경 요청의 출처 검사와 공유 이미지 주소에 사용합니다.
3. `/admin`을 열고 운영 주체, 개인정보 문의처, 행사 종료 후 보관 기간, 공식 인스타그램 주소를 저장합니다. 공개 모드에서는 로그인이 필요 없습니다. 임의의 학과나 연락처는 기본값으로 넣지 않았습니다.
4. 문항·채점·동률·추첨 규칙과 개인정보 안내를 확인합니다. 설정을 저장한 뒤 ‘이벤트 시작하기’를 누르고 확인 문구를 입력합니다. **시작 후 안내 수정, 초기화, 마감 후 재개는 지원하지 않습니다.**
5. 배포 사이트의 공개 범위를 확인합니다. 현재 GitHub Pages, 이벤트 서버, 운영실은 공개되어 있습니다. 로그아웃한 휴대폰에서 참여 주소를 확인한 뒤 관리 화면의 QR을 게시합니다. localhost QR은 다른 휴대폰에서 사용할 수 없습니다.
6. 행사 종료 시 ‘응답 마감하기’에서 `응답 마감`을 입력합니다. 이 순간 제출된 응답을 고정하고 최종 점수를 계산합니다.
7. ‘당첨자 선정’에서 `당첨자 추첨`을 입력합니다. 결과는 한 번만 저장되며 새로고침이나 재요청으로 바뀌지 않습니다. 학과 인스타그램에는 본인 확인에 필요한 최소 정보만 직접 발표합니다. 자동 게시나 관람권 발송 기능은 없습니다.
8. 필요하면 CSV를 내려받습니다. 공개 운영실에서는 이름·학번·완료 문항 수·점수·당첨 결과를 누구나 열람할 수 있으며 CSV도 내려받을 수 있습니다. 참가자는 등록 전 이 공개 범위에 동의해야 합니다. 정한 보관 기간이 지나면 아래 삭제 절차를 수행합니다. 이미 다른 이용자가 내려받은 사본은 사이트에서 회수할 수 없습니다.

## 점수와 추첨 규칙

- 각 문항의 득표수가 적은 순서대로 5·3·1·0점을 줍니다. 0표 선택지도 순위 계산에 포함합니다.
- 같은 득표수는 공동 순위로 처리하고 다음 순위를 건너뜁니다. `[5, 5, 10, 20] → [5, 5, 1, 0]`, `[0, 0, 0, 20] → [5, 5, 5, 0]`입니다.
- 10문항 합계는 0~50점입니다. 진행 중 값은 잠정값이며 응답 마감 때 확정됩니다.
- 중도 이탈자가 이미 제출한 응답도 문항별 분포에 포함하지만 추첨은 10문항 완료자만 대상으로 합니다.
- 최고점 완료자가 2명 이상이면 그중 2명을 무작위로 선정합니다. **단독 최고점이면 해당 참가자를 선정하고 차순위 점수 참가자 중 1명을 추가 선정**하도록 보완했습니다. 원래 기획에 없던 예외 규칙이므로 운영 안내에 명시했습니다.
- 완료자가 1명뿐이면 1명만 선정하고, 0명이면 추첨을 막습니다. 보안 난수와 비복원 추출을 사용합니다.

## 개발 실행

Node.js 22.13 이상과 npm을 사용합니다. 이 작업 환경에서는 Windows Node.js 24로 검증했습니다.

```bash
npm ci
cp .env.example .env
# .env의 로컬 설정을 입력한 뒤 실행
npm run db:migrate
npm run dev
```

`.env`는 Git에서 제외됩니다. Sites 개발 서버가 출력하는 로컬 테스트 로그인 계정만 로컬 `ADMIN_EMAILS`에 등록합니다. `SITE_URL`은 개발 서버에 표시되는 주소와 같아야 합니다. 로컬 테스트 계정을 실제 배포 설정에 넣지 마세요.

```bash
npm test
npm run typecheck
npm run lint
npm run build
```

테스트는 Node test runner, React Testing Library/JSDOM, 격리된 Miniflare D1을 사용합니다. 실제 행사 DB에 테스트 참가자를 넣지 않습니다. 규칙, 동시·중복 제출, 마감 경합, 세션 복원, 접근 통제, 오류 재시도, 10문항 완료와 추첨을 검사합니다. 브라우저 화면 테스트는 별도입니다.

스키마 변경 시 `npm run db:generate`로 SQL을 생성하고 `drizzle/`의 결과를 검토합니다. 로컬 DB에는 `npm run db:migrate`를 실행합니다. 호스팅에는 Sites 패키징·배포 절차로 마이그레이션을 포함합니다. 요청 처리 중 DDL을 실행하지 않습니다.

## 데이터와 보안 경계

- 참가 세션은 30일 유효합니다. 서버 사이트에서는 HttpOnly·SameSite=Lax·Secure 쿠키를 사용하고, GitHub Pages에서는 브라우저 저장소의 임의 토큰을 Authorization 헤더로 보냅니다. Pages는 타사 쿠키에 의존하지 않습니다. DB에는 원문 대신 SHA-256 해시를 저장합니다. Pages와 서버 브라우저 세션은 별개이므로 행사에서는 동일한 Pages 주소를 안내하세요.
- 등록 요청 전에 브라우저에 세션을 발급해, 응답이 유실되어도 재시도로 기존 등록을 복구합니다. 동일 학번으로 다른 기기의 기록을 조회하거나 이어받을 수 없습니다.
- 학번 중복 제한은 실제 재학생 인증이 아닙니다. 가짜 학번·다중 브라우저 참여를 완전히 막지는 못합니다. 경품 수령 때 학생증 등으로 운영자가 확인해야 합니다.
- `PUBLIC_ADMIN_ACCESS`가 정확히 `true`일 때만 관리자 페이지와 API를 익명에게 개방합니다. 기본값은 `false`입니다. 비공개 모드는 Sites가 인증한 사용자 헤더와 이메일 허용 목록을 모두 확인합니다. 원본 요청의 인증 헤더를 제거·덮어쓰는 Sites 경계가 전제이므로 별도 Worker 주소로 인증 게이트를 우회해 배포하지 마세요.
- 공개 모드는 가입 화면에서 공개 범위를 안내하고 동의를 받습니다. 서버는 `publicAdminConsent: true`가 없는 이전 화면의 등록을 거절합니다. 안내 버전이나 공개 모드가 바뀌면 가입 동의가 초기화됩니다. 이미 수집한 비공개 데이터를 소급 공개하는 운영은 별도로 검토해야 합니다. 이번 전환은 기존 참가자 0명인 시작 대기 상태에서 진행했습니다.
- 변경 요청은 동일 출처와 입력 크기를 검사하고, 토큰·IP 기반 요청 제한을 적용합니다. 참여 API는 다른 참가자의 이름·학번·개별 선택을 반환하지 않지만 **공개 관리자 API와 CSV는 명단을 제공합니다.** 마감·추첨 확인창은 실수 방지용이며 권한 제한 장치가 아닙니다.
- 참여 API는 미응답 문항의 분포를 차단합니다. **공개 운영실에서는 응답 전에도 전체 문항 통계를 볼 수 있으므로 집계 비공개와 참가자 간 판단 독립성은 보장되지 않습니다.** 제출 후 수정·순서 건너뛰기·마감 후 추가 응답은 계속 거절합니다.
- 마감은 하나의 SQLite 문장으로 상태와 집계를 함께 고정합니다. 추첨은 행사별 유일 제약으로 한 번만 저장합니다.
- 자동 분석 도구, 이름·학번을 URL에 싣는 공유 기능, 공개 순위표는 없습니다.

## 보관 기간 종료 후 삭제

**자동 삭제는 구현되어 있지 않습니다.** 운영자는 약속한 기간에 수집 정보, 추첨 기록, 내려받은 CSV와 별도 보관본을 삭제해야 합니다. 실제 운영 주체의 개인정보 절차를 확인한 뒤 진행하세요.

행사를 마감하고 경품 지급·이의 확인이 끝난 뒤, 권한 있는 DB 관리 도구에서 다음 순서로 삭제합니다. 되돌릴 수 없으며 참가자의 결과 재조회도 종료됩니다. 테스트나 행사 시작 과정에서 실행하지 마세요.

```sql
DELETE FROM draws;
DELETE FROM answers;
DELETE FROM participants;
DELETE FROM rate_limits;
```

`events.final_counts`에는 개인을 식별할 수 없는 선택지별 합계만 남습니다. 행사 상태를 다시 열거나 새 참가자를 받지는 않습니다. 호스팅 제공자의 백업·복구본 보관 정책도 운영자가 확인해야 합니다.

## 프로젝트 구조

- `app/lib/questions.ts`: 사용자 원문 10문항·40개 선택지.
- `app/lib/rules.ts`: 채점, 추첨, CSV 셀 안전 처리.
- `app/server/service.ts`: D1 저장·집계·마감·추첨.
- `app/server/api.ts`: HTTP 동작, 인증·세션·출처 검사.
- `app/components/`: 참가·운영 화면.
- `db/schema.ts`, `drizzle/`: 스키마와 생성된 마이그레이션.
- `tests/`: 격리된 데이터·API·화면 테스트.
- `.openai/hosting.json`: Sites 식별자와 논리 DB 바인딩만 보관. 비밀값은 넣지 않습니다.

검정·초록 시각 체계와 Lucide 아이콘을 사용합니다. `public/og.png`는 이번 이벤트를 위해 생성한 공유 이미지이며 공식 영화 포스터나 실제 장면이 아닙니다. 문항은 사용자가 제공한 이벤트 시나리오입니다.

## GitHub Pages 배포

- 참여 사이트: https://dhoklim.github.io/colony-resistance/
- 서버·운영실: https://colony-resistance.dhoklim.chatgpt.site/admin
- 소스 저장소: https://github.com/dhoklim/colony-resistance

`github-pages/`는 기존 소개·참여 컴포넌트를 재사용하는 정적 진입점입니다. 해시 경로 `#/participate`로 이동하므로 직접 링크와 새로고침도 동작합니다. 페이지 리디렉션이나 iframe 대체물이 아니며, 참여 화면은 GitHub Pages에서 실행됩니다.

`npm run build:pages`로 `dist-pages/`를 만듭니다. main 브랜치에 푸시하면 `.github/workflows/pages.yml`이 빌드한 정적 파일만 GitHub Pages에 배포합니다. DB와 서버 코드는 정적 배포물에 포함하지 않습니다. 서버 변경은 기존 Sites 빌드·배포 절차가 별도로 필요합니다.

서버 환경 설정:

- `PARTICIPANT_ORIGIN=https://dhoklim.github.io`: 허용하는 참여 화면 출처. 와일드카드 CORS를 사용하지 않습니다.
- `PARTICIPATION_URL=https://dhoklim.github.io/colony-resistance/#/participate`: 운영실에서 만드는 행사 QR의 주소.
- `SITE_URL`: 기존 서버의 정확한 HTTPS 주소를 유지합니다.

Pages 출처의 CORS 요청은 참가용 API에만 허용합니다. 관리자 화면은 기존 서버 주소에서 열며, 공개 운영 모드에서는 관리자 API도 로그인을 요구하지 않습니다. 공개 여부는 서버 설정으로만 결정하며 브라우저 요청으로 변경할 수 없습니다. Pages가 저장하는 참가 토큰은 본인 답변 제출 권한이 있으므로 URL·로그·공유 메시지에 넣지 마세요. GitHub Pages의 같은 계정 내 다른 프로젝트도 동일한 브라우저 출처를 공유하므로, 신뢰할 수 없는 스크립트를 해당 계정의 Pages에 게시하지 마세요.
